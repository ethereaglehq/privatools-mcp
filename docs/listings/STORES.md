## Critical Gotchas Summary (Verify Before Any Submission)

1. **Smithery Shutdown (`2026-10-31`):** Per [smithery.ai/future](https://smithery.ai/future), Smithery's proxy, hosted servers, accounts, API, `@smithery/cli`, `server.smithery.ai`, and `run.tools` shut down on **2026-10-31**. `/new` and `/submit` return HTTP `404`. Do **not** commit a legacy `smithery.yaml`. See [`smithery-legacy-note.md`](./smithery-legacy-note.md).
2. **PulseMCP Cloudflare Gate:** Direct automated HTTP fetches to `pulsemcp.com/servers` and `pulsemcp.com/submit` receive Cloudflare `403`. Never attempt automated scraping/bypass — open `https://www.pulsemcp.com/submit` manually in a normal browser to inspect current required fields and whether login is required before submitting.
3. **Anthropic Standalone `.mcpb` Directory Deprecation + Read/Write Tool Separation:**
   - Anthropic's Claude Directory no longer accepts standalone `.mcpb` submissions; local MCP servers must be wrapped inside a **Claude Plugin** (public GitHub repo) submitted via `https://claude.ai/directory/manage`. `.mcpb` bundles remain supported for local Claude Desktop one-click install, GitHub Releases, and Official MCP Registry (`registryType: "mcpb"`).
   - Anthropic's Connectors Directory review **rejects** any single tool that mixes safe read actions with destructive write actions — keep destructive deletion strictly isolated in `privatools_delete_job` (`destructiveHint: true`) separate from read-only `privatools_job_status` (`status`/`download` only, `readOnlyHint: true`), with every tool declaring `title` + `readOnlyHint`/`destructiveHint`.
4. **`punkpeye/awesome-mcp-servers` Mandatory Glama Backlink:** Merge into `punkpeye/awesome-mcp-servers` requires an active **Glama** listing AND a visible Glama backlink/badge on our README or website. Submit/claim **Glama first**, add the Glama badge, *then* open the `punkpeye` PR. Also note `wong2/awesome-mcp-servers` closed PRs (submit via `https://mcpservers.org/submit`) and `appcypher/awesome-mcp-servers` is archived (`2026-05-06`).
5. **`mcp-publisher` GitHub Organization Auth Rule:** Interactive `mcp-publisher login github` (device flow) **fails for GitHub organizations** like `ethereaglehq` (upstream tracking issue [#1468](https://github.com/modelcontextprotocol/registry/issues/1468)). PrivaTools uses the canonical **`io.github.ethereaglehq/privatools`** namespace (root `server.json`) published exclusively via **GitHub Actions OIDC** (`mcp-publisher login github-oidc` with `permissions: { contents: read, id-token: write }`) in `.github/workflows/publish.yml` — zero DNS TXT records, zero private keys, and zero PATs.
6. **npm Trusted Publishing 2-Day First-Publish Expiry & Manual Approval Gate:** `.github/workflows/publish.yml` is strictly **manual-only (`workflow_dispatch`, `dry_run: true` by default)** and requires approval on the **`mcp-publish`** GitHub Actions environment before npm, OCI, or Official MCP Registry publishing runs. After creating `@privatools/mcp` on npm, configuring the `mcp-publish` environment with Required Reviewers, and configuring Trusted Publishing (`ethereaglehq` / `privatools-mcp` / `publish.yml` / environment `mcp-publish`), the **first successful OIDC publish MUST execute within 2 days** or npm expires the trusted publisher configuration. Dispatch `publish.yml` manually with `dry_run: false` and `publish_npm: true`, approve the `mcp-publish` gate, and then lock npm settings to *"Require two-factor authentication and disallow tokens"*.
